# FFE — игра на насмотренность и канал о смыслах в моде

Общение с автором — **по-русски**. Автор — исследовательница моды, не инженер: объясняй причину поломки, а не только правку.

## Что здесь лежит

| Папка | Что это | Где крутится |
|---|---|---|
| `frontend/` | Next.js: публичная игра, страницы образов, админка под `/admin/*` | Vercel |
| `backend/` | Express + Postgres: образы, рендеры, загрузки, привязка пинов Pinterest | отдельный сервис |
| `channel/` | Телеграм-канал о смыслах в моде: сбор ленты, разбор, тексты, бот, тренды | Railway, проект `cozy-benevolence`, своя база |

**Деплоя три, и они независимы.** Правка в `frontend/` едет через Vercel, в `channel/` — через Railway, в `backend/` — своим сервисом. Если правка затрагивает две части, пользователь увидит их не одновременно; об этом стоит предупреждать.

## Договорённости

- **Мерджить только по прямому «смерджи»** от автора. PR открывать можно всегда, мерджить — нет.
- Перед добавлением источника в ленту — **живой запрос** (`curl` или `rss-parser`), а не вера в документацию. Мёртвые и заблокированные ленты записывать в PR, чтобы их не добавляли снова.
- Правки проверять на **отдельной базе** (`createdb channel_tNN`, миграции, прогон, `dropdb`), а не на проде. Доступа к проду у сессии нет и не должно быть.
- **Токены и ключи не запрашивать и не печатать.** Они живут в переменных Railway и Vercel. Если правка требует ключа, честно сказать, что живьём проверить нельзя, и описать, как автор проверит сама.
- Ошибки в тексте постов — это не «модель галлюцинирует», а дыра в промпте или в проверке. Искать причину в коде.

## Канал: конвейер поста

Сбор ленты → группировка в сюжеты → оценка → справка из веба → скелет по Минто → разбор → текст → литредактура → проверка на шаблоны → картинка → решение автора в боте.

Описание живёт в `channel/src/assembly.js` и показывается на странице `/admin/assembly` — **оно собирается из кода**, поэтому при изменении конвейера надо править и его.

Ключевые модули:

- `sources.js` — полсотни лент с описанием и тегами; `collect.js` — сбор, шумовые фильтры, диагностика того, что пришло вместо ленты;
- `prompts.js` — все промпты: оценка, скелет (пирамида Минто, тип изменения, ход), разбор, письмо, литредактура. `formats.js` — 14 форматов, цикл на две недели;
- `research.js` — справка о происхождении вещи через серверный поиск Anthropic (`WEB_RESEARCH=off` выключает);
- `slop.js` — детектор шаблонов и выдуманного личного опыта автора; `style/guide.md` и `style/examples/*.md` — голос канала, образцы важнее правил;
- `trends.js` — темы, упоминания, регионы, категории вещей, Google Trends, Pinterest; `pinterest.js` — OAuth с самообновлением маркера;
- `bot.js`, `actions.js`, `telegram.js` — бот владельца; `api.js` — закрытый API для админки (заголовок `x-channel-token`).

Переменные канала: `DATABASE_URL`, `ANTHROPIC_API_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHANNEL_ID`, `TELEGRAM_OWNER_CHAT_ID`, `CHANNEL_API_TOKEN`, `PINTEREST_*`, `WEB_RESEARCH*`, `PUBLISH_HOURS`, `PIPELINE_INTERVAL_HOURS`, `PIPELINE_TIMEOUT_MIN`.

## Админка

`/admin` — образы игры, `/admin/channel` — посты канала, `/admin/trends` — тренды, `/admin/sources` — источники, `/admin/assembly` — как собирается пост.

Доступ — GitHub через next-auth; пускает только логины из `ADMIN_GITHUB_LOGIN` (Vercel). Страницы под `getServerSideProps` с `withAuth(ctx)` — это **проверка внутри `getServerSideProps`, не обёртка компонента**. Запросы к каналу идут через прокси `frontend/pages/api/channel-*`, которые держат `CHANNEL_API_TOKEN` на сервере; в браузер он не попадает. **Добавляя параметр в API канала, не забудь провести его через прокси** — на этом уже ловились: фильтр категорий молча не работал, потому что прокси не передавал `category`.

## Грабли, на которые уже наступали

- **Браузерный User-Agent ломает ленты.** Полный Chrome-подобный `User-Agent` включает защиту у Launchmetrics, Just Style и Who What Wear. Нужен короткий `Mozilla/5.0`.
- **Подсказки Google подбираются по началу строки:** `bra` → «brawl stars», `skirt` → «skirt steak». Спасают якорь `«{термин} trend»`, запрос по русской подписи и отбор моделью.
- **У Pinterest нет России** в списке регионов трендов. Российский спрос — только через Google Trends.
- **RSS-автопубликация Pinterest не возвращает id пинов**, поэтому привязка пина к рендеру остаётся ручной. Домен можно привязать только к одному аккаунту Pinterest.
- **Прогон переживает перезапуск плохо:** деплой посреди прогона уносил и работу, и сообщение о ней. Отметка `run_started` в базе и весть о срыве при старте — оттуда.
- **Дешёвые операции не должны ждать прогона.** Склейка форм единственного и множественного числа выполняется при старте сервиса: прогон идёт раз в 12 часов, а ждать полсуток ради одного SQL незачем.
- **Telegram:** подпись к фото — 1024 знака, поэтому картинка отправляется крупным превью по ссылке; id канала начинается с `-100`, тире часто оказывается не тем символом (`normalizeChannel` в `telegram.js`).

## Полезные команды

```bash
npm --prefix frontend run build      # проверить сборку админки и публичных страниц
node --check channel/src/<файл>.js   # быстрая проверка синтаксиса
cd channel && npm run collect        # собрать ленту (нужен DATABASE_URL)
cd channel && npm run run-once       # один прогон конвейера
```

Тесты на отдельной базе: `createdb channel_tNN`, запуск с `DATABASE_URL=postgres://localhost/channel_tNN`, в конце `dropdb channel_tNN`. Тяжёлые модули (`llm`, `telegram`, `library`) удобно подменять через `require.cache`.
